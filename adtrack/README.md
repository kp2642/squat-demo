# 광고 성과 추적 (adtrack)

상담형 업종 사장님이 광고 채널별로 광고비 대비 문의·계약·매출을 한 화면에서 보는 웹 서비스.
요구사항 문서: 「범용적 광고성과추적 · 1차 개발 요구사항」

- 웹 앱: Next.js 16 (App Router, TypeScript)
- DB·로그인: Supabase (PostgreSQL + Auth + 행 단위 보안)
- 배포: Vercel

## 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 기반: 가입·로그인, 사업장 생성, 업종 프리셋, 직원 초대, 사업장 데이터 분리 | 완료 |
| 2 | 추적 코드 + 수집 API: 꼬리표 저장, 폼 자동 감지, 완료 페이지 방식, 출처 판별 규칙표, 중복 합치기 | 완료 |
| 3 | 문의함: 목록·필터·검색, 상태·금액·실패 사유, 직접 등록(유입경로 필수·쿠폰 문구), 출처 수정, 변경 기록 | 완료 |
| 4 | 광고비: 월·채널 입력, 지난 달 복사, 네이버 키워드 CSV, 채널 관리 | 완료 (실제 네이버 CSV 확인 남음) |
| 5 | 성과 화면: 요약 숫자, 한 줄 제안, 채널·키워드 표, 판별 비율, 미입력 경고 | 완료 |
| 6 | 설치 탭과 처음 설정 흐름 | |
| 7 | 실제 업체 테스트 | |

## 1단계에서 만든 것

- **가입** (`/signup`): 이메일·비밀번호·사업장 이름·업종·홈페이지 주소(여러 개). 메일 확인을 켜 둔 경우 확인 링크를 누르면 `/onboarding` 에 입력값이 다시 채워진 채로 돌아와 사업장을 만든다.
- **업종 프리셋** (`industry_presets`): 법률·병원·세무·학원·인테리어·기타. 고르면 계약 용어, 평균 계약 금액, 상담 유형이 채워지고 설치 탭에서 모두 고칠 수 있다.
- **기본 채널**: 네이버 검색광고, 구글·메타·카카오 광고, 블로그·체험단, 네이버 예약·톡톡, 자연 검색, 지인 소개, 직접 방문. 출처 판별 규칙(2단계)이 `code` 로 찾으므로 지울 수 없고 숨길 수만 있다.
- **직원 초대**: 설치 탭에서 이메일과 역할로 초대 링크(7일)를 만들어 복사해 보낸다. 초대받은 이메일로 로그인해야 수락된다. 한 계정은 한 사업장에만 속한다.
- **역할**: 관리자는 4개 탭 전부, 직원은 문의함만. 직원은 자기 이름 외에는 설정을 바꿀 수 없다.
- **데이터 분리**: 모든 사업장 테이블에 `workspace_id` 와 RLS 정책. 사업장·사용자 생성과 초대 수락은 `security definer` 함수(`create_workspace`, `accept_invitation`)로만 가능하고, 수정 가능한 열도 grant 로 제한한다(역할·추적 키·`workspace_id` 는 바꿀 수 없음).

## 2단계에서 만든 것

- **추적 코드** (`tracker/tracker.js` → `npm run build:tracker` → `src/generated/tracker.ts`): 의존성 없는 순수 JS, 압축 후 약 4.3KB(gzip 2.3KB).
  `<script async src="https://<서비스>/t/<추적키>.js">` 로 넣으면 `/t/[file]` 경로가 사업장 설정(완료 페이지 주소)을 넣어 내려주고 5분 캐시한다.
  - 방문 시 꼬리표(`n_*`, `utm_*`, `gclid`, `fbclid`)와 외부 유입 주소를 첫 파티 쿠키(90일)에 ‘첫 유입’(`_atk_f`)과 ‘마지막 광고 유입’(`_atk_l`)으로 저장. 꼬리표 없는 재방문은 꼬리표 있는 마지막 광고 유입을 덮어쓰지 않는다. `www.`·`m.` 같은 하위 도메인끼리 쿠키를 같이 쓴다.
  - 폼 제출(`submit`, 캡처 단계)을 지켜보다 이름·연락처·상담 유형 칸을 이름/라벨/placeholder 로 추측해 `sendBeacon` 으로 보낸다. 원래 제출은 막지 않는다. `010 / 1234 / 5678` 처럼 나뉜 칸도 잇는다. 연락처가 없는 폼(검색창 등)과 비밀번호 칸이 있는 폼은 무시한다.
  - 문의 완료 페이지 방식: 설치 탭에 주소를 넣으면 그 페이지 도착을 문의 1건으로 센다(이름·연락처는 빈 채로). 방금 폼으로 보냈거나 새로고침이면 다시 세지 않는다.
  - 꼬리표가 있는 방문은 `visits` 에 기록(개인정보 없음), 하루 한 번 신호로 ‘설치 확인됨’.
  - 관리자 본인 제외: 홈페이지를 `?atk_exclude=1` 로 한 번 열면 그 브라우저는 집계하지 않는다 (`?atk_exclude=0` 으로 해제).
- **수집 API** (`/api/collect`): 다른 도메인에서 오므로 CORS 허용. 요청한 홈페이지(Origin)가 추적 키의 사업장에 등록된 도메인(또는 하위 도메인)일 때만 받는다. 같은 방문자 10분 3건, 같은 IP 10분 20건까지.
- **출처 판별** (`src/lib/attribution.ts`): 요구사항의 규칙표 1~7 순서. utm_source 는 사업장 채널의 매핑 값으로 채널을 찾고, 매핑이 없거나 규칙에 없는 외부 사이트에서 오면 ‘출처 미확인’(`attribution = 'unknown'`). 판별 근거(예: `n_keyword=이혼전문변호사`)를 문의에 남긴다.
- **개인정보**: 이름·연락처는 서버에서 AES-256-GCM 으로 암호화해 저장하고(`LEAD_ENCRYPTION_KEY`), 같은 연락처 찾기는 HMAC 해시, 화면 표시는 `010-****-5678`.
- **중복 합치기**: `(workspace_id, phone_hash)` 유일 인덱스로 같은 연락처는 동시에 들어와도 문의 하나. 두 번째부터는 `lead_touches` 에 다시 연락으로 기록하고 출처는 첫 문의 것을 유지한다.

## 3단계에서 만든 것

- **문의함** (`/app/inquiries`): 최신순, 상태 탭(새 문의·상담중·계약 용어·실패), 채널 필터(출처 미확인 포함), 검색, 30건씩 더 보기. 문의함 탭에 새 문의 수 배지.
  - 검색은 이름·연락처가 암호화되어 있어 **정확히 같은 이름**(공백 무시), **전체 번호**, **뒷자리 4개**로 한다.
- **카드**: 이름, 가린 연락처(눌러서 전체 보기·전화 걸기), 문의 방식·상담 유형·시각, 출처 + 키워드·캠페인, 판별 방식(자동·쿠폰 문구·고객 응답·직접 선택·출처 미확인), 판별 근거, 다시 연락 횟수.
  - 상태 버튼: ‘계약’을 누르면 업종 평균 금액이 채워진 칸이 열리고 ‘저장’ → **탭 2번**. ‘실패’는 사유(가격·연락 안 됨·다른 곳 선택·기타)를 누르면 바로 저장.
- **직접 등록** (`/app/inquiries/new`): 전화·방문·기타, 이름·연락처·상담 유형, ‘어떻게 알고 오셨어요?’ 채널 필수. 쿠폰·암호 문구가 채널에 등록돼 있으면 그 채널이 자동으로 골라지고(판별 방식 ‘쿠폰 문구’), 아니면 ‘고객 응답’. 같은 연락처가 있으면 새 문의 대신 다시 연락으로 기록한다. 쿠폰 문구는 설치 탭에서 채널별로 정한다.
- **상세** (`/app/inquiries/[id]`): 첫 유입·마지막 광고 유입, 상태 수정, 출처 바꾸기(→ ‘직접 선택’, 원래 값은 기록에 남음), 고객 응답 추가(출처는 그대로), 이름·연락처 채우기(완료 페이지 방식 문의), 다시 연락 목록, 변경 기록(누가·언제·무엇을), 관리자만 지우기.
- **변경 기록** (`lead_events`): DB 트리거가 상태·금액·실패 사유·출처·판별 방식·고객 응답·이름·연락처·상담 유형 변경을 남긴다. 이름·연락처는 값을 남기지 않는다(연락처는 가린 번호만). 사용자가 직접 쓰거나 지울 수 없다.
- 화면이 쓰는 읽기·쓰기는 DB 함수(`inbox_list`, `lead_detail`, `update_lead_status` 등)로 모았고, 직접 등록 말고는 부르는 사용자 권한(행 단위 보안)으로 실행된다.

## 4단계에서 만든 것

- **광고비** (`/app/spend`, 관리자만): 달을 넘기며 채널별 월 광고비 입력(빈 칸은 그 달 금액 지움), 지난 달 금액 복사(이번 달에 비어 있는 채널만, 숨긴 채널 제외), 채널 추가·이름·종류·utm_source 매핑·숨기기.
- **네이버 키워드 보고서 CSV** (`src/lib/naver-csv.ts`): 올리면 그 달 키워드 광고비를 파일 내용으로 바꾸고, 원하면 네이버 검색광고 월 광고비도 키워드 합계로 맞춘다. 키워드 직접 입력·지우기도 된다.
  - 받는 형식: UTF-8(BOM)·EUC-KR, 쉼표·탭, 위쪽 제목·기간 줄, 따옴표 없는 `총비용(VAT포함,원)` 머리글, `"1,234"`·`-`·소수점 숫자, 광고그룹·날짜별 여러 줄(합침), 합계 줄(뺌).
  - 파일 기간(제목 줄의 `A ~ B` 또는 일별 칸)이 고른 달과 다르거나 여러 달이면 막는다. 엑셀(.xlsx)은 CSV 로 다시 받으라고 안내한다.
  - 못 읽으면 찾은 칸 이름을 오류에 보여 준다. **실제 네이버 파일로는 아직 확인하지 못했다** — 테스트 파일(`tests/fixtures/naver/`)은 알려진 형식을 본떠 만든 것이다. 실제 파일이 안 들어가면 오류 문구의 칸 이름으로 `naver-csv.ts` 의 머리글 규칙을 고친다.
- 비용은 파일에 적힌 그대로(보통 VAT 포함) 저장하고, 어느 칸을 읽었는지 알려 준다.

## 5단계에서 만든 것

- **성과** (`/app`, 관리자만): 기간 이번 달(1일~오늘, 기본)·지난 달·최근 30일·직접 지정. 모든 지표는 그 기간에 **등록된 문의** 기준(한국 시간 날짜).
  - 요약: 광고비, 문의(전환율), 계약, 계약 매출, ROAS(+ 광고비 1원당 매출), 문의당 비용, 계약당 비용.
  - 한 줄 제안: 문의 5건 이상인 유료 채널 중 ROAS 가장 높은 곳과 낮은 곳.
  - 채널별 표(휴대폰에서는 채널 카드), 네이버 키워드별 표(키워드 광고비를 넣었을 때만), 출처 판별 비율(자동·쿠폰·고객 응답·직접 선택·미확인), 7일 지난 미입력 문의 경고.
- **계산 규칙**: 집계는 DB 함수 `performance()`, 비율·ROAS·딱지·제안은 `src/lib/performance.ts`.
  - 광고비가 월의 일부만 들면 `월 금액 × (든 일수 ÷ 그 달 일수)`, 채널별로 더한 뒤 원 단위 반올림.
  - 분모 0이면 문의당·계약당 비용 ‘-’, 전환율 0%, 광고비 0이면 ROAS ‘-’·‘무료 유입’. 광고비 없는 채널은 문의당·계약당 비용도 ‘-’.
  - 판단 딱지: 무료 유입 > 문의 5건 미만 표본 부족 > ROAS 기준(사업장 설정, 기본 500%/200%).
  - 키워드는 띄어쓰기·대소문자를 무시하고 맞춘다(네이버 검색광고 문의의 키워드와 키워드 광고비).
- **완료 기준 확인**: 예시 데이터(`tests/fixtures/performance-example.mjs`)를 손으로 계산한 값(`tests/unit/performance.test.ts` 맨 위 주석)과 화면 숫자를 브라우저 테스트가 하나하나 비교한다. 문의 1만 건 사업장에서 집계 약 0.1초.

## 테스트

```bash
npm install
npm test           # 단위 테스트
npm run test:db    # 데이터 분리 테스트 (아래 참고)
npm run typecheck
```

`test:db` 는 PostgreSQL 에 Supabase 의 역할·`auth.uid()` 를 흉내 내는 `tests/db/supabase-shim.sql` 과 마이그레이션을 적용한 뒤,
두 사업장을 만들어 모든 테이블에서 읽기·수정·삭제·추가가 서로 막히는지 확인한다.
shim 은 Supabase 처럼 기본 권한을 모두 열어 두므로, 테스트가 통과하는 건 마이그레이션의 정책 덕분이다.
`workspace_id` 열이 있는 테이블은 새로 생겨도 자동으로 검사 대상이 된다.

`test:e2e` 는 네 가지를 본다.

- **성과** (`tests/e2e/performance.test.mjs`): 예시 데이터의 요약 숫자·채널 표·키워드 표·제안·판별 비율·경고를 손 계산과 비교, 월 일부 기간 광고비 나누기, 휴대폰 카드, 직원 접근 막기.

- **광고비** (`tests/e2e/spend.test.mjs`): 휴대폰 화면에서 금액 입력·지난 달 복사, 테스트 CSV 4종을 실제 파일 올리기로 넣기, 못 읽는 파일·다른 달 파일 거절, 키워드 직접 입력, 채널 추가·숨기기, 직원 접근 막기.

- **문의함** (`tests/e2e/inbox.test.mjs`): 400px 터치 화면에서 ‘계약 + 금액’까지 탭 수를 세고(완료 기준 3번 이하 → 2번), 실패 사유, 직접 등록·쿠폰 문구, 중복 연락처, 출처 수정과 변경 기록, 검색·필터, 직원 권한, 가로 스크롤 없음을 확인한다.
  Supabase Auth·REST 서버 없이 돌리기 위해 테스트에서만 켜지는 서명 쿠키 로그인(`src/lib/test-auth.ts`)과, 같은 DB 함수를 PostgreSQL 에 사용자 역할로 직접 부르는 경로(`src/lib/user-db.ts`)를 쓴다.
  `ADTRACK_TEST_AUTH_SECRET` 과 `DATABASE_URL` 이 둘 다 있을 때만 켜지고 Vercel 에서는 켜지지 않는다. **운영 환경에는 이 두 값을 함께 넣지 말 것.**
- **추적 코드**: 실제 Chromium 으로 테스트용 홈페이지 3종(`tests/e2e/sites.mjs`: 일반 HTML 폼, 워드프레스 Contact Form 7 모양, 아임웹 모양 빌더형)에

## Supabase 연결

1. Supabase 프로젝트를 만들고 `supabase/migrations/` 의 SQL 을 순서대로 실행한다 (SQL Editor 또는 `supabase db push`).
2. `.env.example` 을 `.env.local` 로 복사해 프로젝트 URL, anon 키, service_role 키, 암호화 키(`openssl rand -base64 32`)를 넣는다.
3. Authentication → URL Configuration
   - Site URL: 서비스 주소 (로컬은 `http://localhost:3000`)
   - Redirect URLs: `<서비스 주소>/auth/confirm`
4. Authentication → Providers → Email: **Confirm email 을 켜 둔다.** 초대 수락은 로그인한 이메일과 초대 이메일이 같은지로 확인하기 때문.
5. `npm run dev`

Vercel 에 배포할 때는 루트 디렉터리를 `adtrack` 으로 두고 같은 환경 변수를 넣는다. 추적 코드(`/t/...js`)는 Vercel CDN 에서 5분 캐시된다.
